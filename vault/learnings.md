# Learnings — myPortfolio

## [2026-07-10] macOS dock/window metaphor in motion (Framer Motion)

**Context:** Rebuilt the portfolio as a macOS desktop SPA (dock magnification, draggable windows, minimize-to-dock).

**Learnings:**
- **Dock magnification** is three motion primitives: dock-level `useMotionValue(Infinity)` fed by `onMouseMove(e.pageX)`, per-icon `useTransform(distance, [-150,0,150], [48,84,48])`, wrapped in `useSpring({mass:0.1, stiffness:170, damping:12})`. Reset to `Infinity` on mouse leave or icons stick enlarged.
- **Icon scaling:** lucide-react accepts `size="100%"` — wrap the icon in a `52%`-sized box inside the tile so the glyph scales with the magnified tile instead of staying fixed-px.
- **Layer drag and programmatic animation separately.** A window needs an OUTER motion.div owned by `useAnimationControls` (open/minimize/restore) and an INNER motion.div owning `drag` — combining them on one element makes the minimize animation fight the drag x/y motion values.
- **Minimize-to-dock targeting:** keep a ref map (`iconRefs` on the window-manager context, refs not state) that DockIcons register into; on minimize, diff `getBoundingClientRect()` centers and animate the delta. Keep minimized windows mounted (pointer-events: none) so restore can reverse the animation and drag position survives.
- **Terminal-style components must not use theme CSS variables** for text: over a fixed dark pane, light-theme values of `--color-text-muted` become dark-on-dark. Hard-code the dark palette inside the pane.
- **Playwright without downloads:** `playwright-core` + `chromium.launch({ channel: 'chrome' })` drives installed Google Chrome — no 130MB browser download for a screenshot verification loop.

## [2026-07-11] Dock/typewriter layout-isolation patterns

- **Fixed-height dock bar with magnifying icons:** the in-flow element per icon must be a *slot* that animates only `width` (fixed `height: 48`); the visible tile is `position:absolute; bottom:0` inside it with `height` driven by the same spring MotionValue. Growth escapes upward out of the bar, so the bar never stretches. Tooltip/bounce/running-dot anchor to the slot or the bottom-anchored wrapper.
- **Zero-reflow typewriter:** render an invisible sizer (`visibility:hidden`, longest phrase) in flow and the live typed text `position:absolute; inset:0` on top. Peers never shift during type/delete. Compute the longest phrase from the array (`reduce` by length), don't hard-code it.
- **Playwright verification of "no layout shift":** sample `getBoundingClientRect().y` of peer elements across the animation cycle into a `Set` of fixed-precision strings — set size 1 ⇒ stable. Same trick for the dock: compare bar height before/during a mouse hover sweep.
- **Playwright launches with light color-scheme by default** — a theme-context site renders light even if its CSS default is dark. Seed with `context.addInitScript(() => localStorage.setItem('theme','dark'))` + `colorScheme:'dark'` to verify the dark theme.

## [2026-07-11] Phase 3: AI proxy, Spotlight, OS interactions

- **Static SPA + secret API key = Vercel Edge Function proxy.** `api/chat.ts` at repo root with `export const config = { runtime: "edge" }` auto-routes on Vercel next to a Vite `dist`. Guardrails that matter: strip client `system` messages and inject the system prompt server-side (kills prompt-injection spend abuse), cap messages/chars, Origin-header same-host check, best-effort per-isolate rate-limit Map.
- **Edge handlers are unit-testable without Vercel:** transpile the TS with the project's own esbuild (`transformSync(src, {loader:'ts'})`), import the emitted module in Node ≥18 (global Request/Response), and assert on handler(Request) statuses. All 6 hardening paths verified this way in seconds.
- **Zoom + framer drag:** window drag offset must live in explicit `useMotionValue`s passed to the draggable's style — programmatic zoom then animates them back to 0; otherwise the stale drag transform offsets the zoomed rect.
- **Rounded windows clip resize handles:** `overflow:hidden` + border-radius clips hit-testing at the extreme corner pixels; grab points must be ≥ radius/2 inset (test at −6px, not −3px).
- **Qwen 3.x on OpenRouter are hybrid reasoning models** — a bare "say hello" burned 4,213 reasoning tokens (~$0.005, ~30s) and the SSE stream looked empty because every delta was reasoning, not content. Fix: `reasoning: { enabled: false }` in the request body (~350× cheaper, instant). Also: `qwen/qwen-turbo` no longer exists as a model id — current cheap chat tier is `qwen/qwen3.6-flash`; list live ids via GET /api/v1/models.
- **Vite dev can serve Vercel edge functions:** a `configureServer` plugin that `ssrLoadModule("/api/chat.ts")`s the handler and bridges Node req/res ↔ web Request/Response makes `/api/*` work under plain `npm run dev` — no `vercel dev`, no login. Load non-VITE_ env vars with `loadEnv(mode, cwd, "")` and copy them onto `process.env`.
- **WebAudio UI sounds need no assets** — short oscillator blips with exponential gain decay (sine pop for open, triangle down-sweep for minimize) read as "macOS-ish"; lazily create AudioContext on first gesture and guard everything in try/catch.

## [2026-07-11] Phase 4: CI/CD ship convention

- **Ship flow for this repo:** feature done → ask KC "commit & push to main?" → on yes, conventional commit(s) direct to main → `git push origin main`. GitHub Actions (`.github/workflows/ci.yml`) runs `npm ci && npm run build` as the gate; **deployment is Vercel Git integration** (push to main auto-deploys production) — deliberately NOT in the Actions workflow, so no Vercel tokens live in GitHub.
- Never push without asking; never commit `.env` (`OPENROUTER_API_KEY` lives only in local `.env` + Vercel env vars). `vault/dispatch-log.md` is gitignored noise; this file is committed.

## [2026-07-13] Phase 5: free-only KAI + Projects parallax previews

- **KAI is free-only now:** `api/chat.ts` defaults to `qwen/qwen3-next-80b-a3b-instruct:free` and the `OPENROUTER_MODEL` override is honored only if it ends in `":free"`. OpenRouter `models: [...]` array gives automatic fallback routing — free models 429 individually ("temporarily rate-limited upstream", provider Venice) even when the account's daily quota is untouched, so a fallback chain (`qwen3-coder:free`, `llama-3.3-70b-instruct:free`) + mapping upstream 429 → friendly 429 matters more than the model choice. Verified the guard with the esbuild-transpile + mocked-fetch unit trick (capture the request body, assert `model`/`models`).
- **Projects previews:** screenshots auto-discovered via `import.meta.glob("../../../assets/projects/*/*.{png,jpg,jpeg,webp}", { eager: true, import: "default" })` keyed by folder slug — adding files needs zero code changes.
- **3D tilt card + overflow:** `overflow: hidden` forces `transform-style` to flat, killing children's `translateZ`. Keep the tilting card overflow-visible with `preserve-3d`, and clip the screenshot inside an inner absolute wrapper (`inset: 0`, borderRadius, overflow hidden) instead.
- **Theme-proof scrim over screenshots:** `linear-gradient(to bottom, color-mix(in srgb, var(--color-surface) 35%, transparent), var(--color-surface) 82%)` keeps card text readable over any screenshot in both themes.
- **Playwright can open OS windows via the app's own CustomEvent** (`window.dispatchEvent(new CustomEvent("kc:spotlight"))` + type + Enter) — no dock selectors needed. Playwright also doubles as a placeholder-screenshot generator (`page.setContent` + `page.screenshot` at 390×844).

## [2026-07-18] Phase 6: SEO — de-indexing fix + crawlable fallback

- **The site was `noindex, nofollow` in `index.html` the whole time** (a Figma Make export default). Single line, no Vercel header or robots.txt reinforcing it — but it silently blocked all indexing since launch. Worth grepping any Make/Figma-exported HTML for this before launch.
- **SSR is the wrong tool for this app.** It's a single-URL macOS desktop shell — `react-router` was installed but never imported, and window state lives in `WindowManagerContext`, not the URL. SSR would have rendered a desktop with zero windows open = still nothing indexable. The right fix was a build-time `transformIndexHtml` plugin (`vite-plugins/seoContent.ts`) injecting real HTML after `#root`, removed by `main.tsx` on mount. Zero new deps, 900 B → 5.9 kB of crawlable content.
- **Cloaking line:** injecting SEO-only HTML is safe *because* identical bytes go to every client, the block is a genuine no-JS fallback, and every claim also appears in the visible UI. Keeping it sourced from one `src/content/profile.ts` that the hero also renders is the mechanism that enforces that — hand-written SEO copy would drift into cloaking.
- **Positioning claims must be checked against the repo, not taken from the brief.** The ask was to advertise "LLM features shipped to production" naming three client apps — but those projects' own descriptions are Firebase/Maps, UIKit customer-service chat, and Kotlin herd management. No LLM anywhere. The real, provable differentiator is AI-*accelerated delivery* (70% debug-time cut). Shipping the original claim would have been a credibility trap for a client who clicks through.
- **Client work here is under NDA — never write client or product names into this repo.** It is (or was) a public GitHub repo, so anything committed is public and permanent in git history. Describe engagements generically ("a regional property group", "an agricultural agency"). This applies to commit messages and vault entries too, not just source.
- **Chrome headless is a usable Playwright substitute** (`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless --screenshot=x.png --window-size=W,H`) and generates OG images at 1200×630 from a `file://` HTML. Gotchas: `--disable-javascript` is **not a real flag** (page still runs JS — strip the `<script>` tag from a copy of `dist/` instead); `--force-prefers-color-scheme` is ignored here, and this app reads its own ThemeContext/localStorage anyway, so force a theme by deleting the `@media (prefers-color-scheme: dark)` block from the test copy; `--virtual-time-budget` **hangs forever** on this app's infinite animations — wrap in `timeout 45`, the screenshot still gets written.

## [2026-07-20] Phase 7: serif typography system + desktop personality

- **The app had zero font tokens — 50 hardcoded `fontFamily` string literals across 16 files.** Introducing a serif meant touching all 50 sites either way, so the move was to define `--font-display / --font-ui / --font-sans / --font-mono` in `theme.css` first and point every site at those. `sed` handled the mono/Inter substitutions (identical strings, mechanical); the Space Grotesk sites needed per-site judgement and were done by hand.
- **The serif/sans split that works here is chrome vs. content, not headings vs. body.** OS chrome (menu bar, window title bars, dock tooltips, Spotlight) stays sans; content headings and names go serif. That mirrors real macOS — system UI is sans, documents are editorial — so the contrast reads as intentional. A 13px display serif in a title bar just looks broken.
- **Fraunces needs its axes set or it's just another serif.** `fontVariationSettings: "'SOFT' 40, 'WONK' 1"` is what makes it look like a choice; `font-optical-sizing: auto` on `body` is the whole reason the variable font earns its bytes (88px hero and 15px card titles want very different contrast). Request the variable range (`opsz,wght,SOFT,WONK@9..144,400..700,0..100,0..1`) — and note `ital` is a *separate* axis: setting `fontStyle: italic` without requesting it gets you a faux-oblique.
- **Two typographic sites that should NOT get the serif** even though they look like headings: a line ending in a blinking terminal cursor (the serif fights the code motif), and label/value data rows where one value is an email address.
- **Only 4 real heading tags existed** — job titles, project card titles and skill categories were styled `div`s, so a `h1,h2,h3 {}` CSS rule would have missed nearly everything. Promoting them to `h3` while editing was free and aligns the live DOM with the heading structure `vite-plugins/seoContent.ts` already advertises.
- **`ThemeContext` was persisting to localStorage inside a mount effect**, which silently pinned every visitor on first load and made "follow the OS" permanently unreachable. Correct shape: persist only in the explicit `toggle()`, and gate the `matchMedia` listener on `!localStorage.getItem("theme")`. Pair it with a blocking inline script in `index.html` — React sets the attribute one frame too late, which is the dark-flash.
- **framer/motion values outlive an `AnimatePresence` exit if they live on the parent.** The sticky note's x/y are `useMotionValue`s on `StickyNote`, while only the inner `motion.div` is conditional — so after "Put back" the note reappeared sitting on the dock where it was dropped. Fix: reset the motion values in an effect keyed on the trashed flag. Also, `info.point` in `onDragEnd` is a *pointer page coordinate*, not the element's offset — persist `x.get()/y.get()` instead.
- **The dead `src/app/components/ui/` shadcn scaffold was costing 56 kB of CSS.** Tailwind's `@source` glob was scanning those 48 unused files and generating classes for them: deleting the folder took the built CSS from 69.3 kB → 11.8 kB (gzip 12.2 → 3.5 kB). Dead code in a Tailwind project is not free.
- **50 of 54 dependencies were unused** (all Radix, MUI, Emotion, recharts, cmdk, sonner, next-themes, react-hook-form…). Removing them exposed a latent bug: `react`/`react-dom` were declared as *optional peerDependencies* (a Figma Make artifact) and were only present transitively — the build broke on `react-dom/client` until they were installed as real dependencies. Worth checking that block on any Make-exported repo.
- **There is no `tsc` in this project**, so `npm run build` (esbuild) strips types without checking them. A green build is not a type check. Adding `typescript` + a `typecheck` script is an open gap.
- **Verifying time-boxed UI (boot splash, idle screensaver) via screenshots:** just temporarily widen the constant (`BOOT_MS`, `IDLE_MS`), shoot, and put it back — racing a 1.9s animation with round-trip tool calls doesn't work. The Chrome extension tooling can drive the app's own `kc:spotlight` CustomEvent to open windows without hunting dock coordinates.

## [2026-07-20] Phase 8: adopting TypeScript on an unchecked codebase

- **The very first `tsc --noEmit` found a live, shipped-to-nobody bug in my own prior commit.** A `sed -i '' 's/\bcardSpring\b/SPRING_CARD/g'` had silently done nothing — **BSD/macOS sed does not support `\b`** — so the declaration got deleted while four usages still referenced `cardSpring`. `vite build` passed anyway, because esbuild strips types and never resolves identifiers. The Projects window would have thrown `ReferenceError` on open; I'd tested Skills/Experience/Trash but not Projects. Two lessons: use `[[:<:]]`/explicit patterns or `perl -pi` for word-boundary renames on macOS, and **a green Vite build is not evidence the code runs.**
- **16 errors total on a ~38-file codebase, and only two were real bugs** — `iconRefs.current` possibly-null at `Dock.tsx:38` and `Window.tsx:150` (the context typed a `useRef({})` as `RefObject`, whose `current` is `T | null`; `StickyNote` guarded it with `?.`, the other two didn't). Fix the *type* at the source (`MutableRefObject`) rather than adding `!` at each call site.
- **The predicted `@types/node` landmine never fired.** Adding node types to a shared config was expected to flip `ReturnType<typeof setTimeout>` from `number` to `NodeJS.Timeout` and break `clearTimeout` in browser code. It didn't — `ReturnType<typeof setTimeout>` is exactly the idiom that stays consistent across both global declarations. Don't pre-emptively rewrite timer code to `window.setTimeout`; wait to see if it actually errors.
- **Config settings this repo genuinely required** (not stylistic): `allowImportingTsExtensions` + `noEmit`, because `main.tsx` imports `"./app/App.tsx"` with the extension; `jsx: "react-jsx"`, because nothing imports React while ~20 files use the `React.*` namespace in type position; `types: ["vite/client"]` for the `.png`/`.jpeg`/`.css` imports and `import.meta.glob`. `src/declarations.d.ts` still has to declare `*.pdf` — **vite/client does not cover pdf**.
- **Deliberately left off:** `noUncheckedIndexedAccess` (not part of `strict`; would have turned 16 errors into ~40, all of the `DAYS[d.getDay()]` variety) and `verbatimModuleSyntax` (would demand `import type` annotations repo-wide). Both are separate, later decisions.
- **Hand-written prop types for third-party components rot.** `apps.ts` declared `icon: ComponentType<{ strokeWidth?: number }>` while lucide's own `LucideProps` allows `string | number` — 9 errors from one wrong assumption. Import the library's exported type (`LucideIcon`) instead of re-describing it.
- **CI was blinder than it looked:** `vite build` never compiles `api/` at all (Vercel builds the Edge function separately at deploy), and only *loads* `vite-plugins/`. A break in `api/chat.ts` reached production without CI ever looking at it. The `typecheck` step's `include` is what finally covers those zones.
- **A React ref on an `AnimatePresence` child trips motion's `PopChild`** into React 18.3's "`ref` is not a prop" warning. Fix by moving the measuring ref to an inner wrapper div — it still inherits the parent's drag transform, so `getBoundingClientRect()` remains correct for hit-testing/clamping.
- **`align-items: safe center` is the fix for centered content clipping in a non-scrollable container.** The hero is a centered flex child inside a `position: fixed` desktop with `body { overflow: hidden }`; when content exceeded the height it overflowed *symmetrically* and the top was unreachable. `safe` falls back to start-alignment exactly when that would happen.
- **Driving headless Chrome over CDP is a better Playwright substitute than `--screenshot`** and works when the Claude-in-Chrome extension drops: launch with `--remote-debugging-port=9222`, then `node --experimental-websocket` (Node 20 has no global `WebSocket` without the flag) to speak raw CDP. `Runtime.evaluate` opens app windows, `Input.dispatchMouseEvent` performs real drags, and subscribing to `Runtime.exceptionThrown` + `Runtime.consoleAPICalled` turns screenshots into an actual error check. Scripts kept in the scratchpad. Gotcha: after editing source, a failed Vite HMR apply leaves the page on the **stale module** — the log line `[vite] Failed to reload` means the screenshot is lying; restart the dev server and `rm -rf node_modules/.vite`.
